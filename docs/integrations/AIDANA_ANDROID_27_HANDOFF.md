# Айдане: исходники Android 2.7 и веб-кошелька

Ветка: `feature/bekzat-persistent-release`, Draft PR #27. Main не объединялся автоматически. Рабочая версия APK: 2.7 (10), пакет `kz.qadamx.bccshield.demo`. Не создавайте второй независимый интерфейс поверх старых dev-экранов.

## Где работать

- `android-app/www/connected.mjs` — серверные действия и навигация; `gateway.mjs` — сессия и запросы.
- `android-app/www/wallet.mjs`, `wallet.css`, `connected.css` — общий продуктовый интерфейс APK и браузера.
- `android-app/www/copy.mjs` и существующие RU/KK строки — локализация.
- `android-app/android/app/build.gradle` — версия и HTTPS origin. По умолчанию saq-bol-mobile.onrender.com; переопределение QADAM_API_ORIGIN только на этапе сборки.
- `backend/app/mobile_gateway/` — серверная граница ролей; клиент не выбирает себе роль.
- `backend/scripts/mobile_accounts.py` — создание отсутствующих локальных файлов паролей. `mobile_demo.py` теперь сохраняет access.json между локальными запусками и отказывается перезаписывать повреждённый файл.

## Сборка и проверки

Из корня: `npm --prefix android-app ci`, затем `npm --prefix android-app test` и `npm --prefix android-app run web`. Для APK: `npm --prefix android-app run sync`, затем из `android-app/android` выполните `gradlew.bat assembleDebug lint` на Windows (Java 21 и Android SDK). Для CI/Linux используйте `./gradlew`. Существующий workflow Android APK выполняет сборку, lint и сверку включённых UI-ресурсов. Ключ подписи для обновления Honor не публикуется; другая debug-подпись не обновит установленный пакет без удаления данных.

`docker compose -f docker-compose.android.yml up -d --build --wait` предназначен для отдельного локального стенда. Его access.json и пароли публичного Render — разные наборы. Не используйте `down -v` для ремонта входа. Не переносите файлы паролей в исходники или APK.
