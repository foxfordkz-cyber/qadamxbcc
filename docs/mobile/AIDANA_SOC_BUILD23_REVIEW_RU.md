# Новый дизайн SOC и единый стенд APK — 25 ноября 2026

## Источник дизайна и границы изменений

Дизайн Айданы получен от команды в `Saq-Bol-2.9-SOC-debug (1).apk`.
SHA-256: `9cc5091047e4185ff0a1574e2b780848a97942fff58498469063aaea0cab2787`.
Это `kz.qadamx.bccshield.dev`, версия 2.9, build 16. Предыдущий файл без `(1)`
отличается тремя UI-файлами: connected.mjs, soc-ui.mjs и soc.css. Последняя
версия добавляет оформление кабинета администратора платформы.

Исходные открытые JS/CSS и пять локальных иллюстраций из переданного APK
перенесены в существующие исходники. Ветка Айданы `design/figma-android`
включена обычным merge, её авторские коммиты сохранены. Новый APK не является
самостоятельным источником backend или изменением антифрод-порогов.

Релизный канал сохраняет пакет `kz.qadamx.bccshield.demo` и прежнюю подпись;
новый номер сборки — 23. Debug-пакет Айданы и релизный пакет различаются:
релиз обновляет прежний `.demo`, а `.dev` остаётся отдельным приложением.
Удаление приложений и очистка данных не выполняются.

## Что объединено

- Отдельный SOC: обзор, лента, причины решения, кейсы, аналитика, граф,
  диагностика и профиль; оформление для телефона и ноутбука.
- Отдельный кабинет `platform_admin`: нагрузка API и управление разрешённым
  доступом сотрудников. Финансовая лента не выдаётся этой роли.
- Граф открывает реальные операции выбранного узла/связи, сохраняет масштаб
  и показывает ссылку на квитанцию. Риск-признак не объявляет человека виновным.
- Сохранены ранее подготовленные Guardian review, история и смена аккаунта.
- Устранены недостоверные обозначения: участники ленты не называются числом
  сетевых сигналов; удержанные деньги не объявляются спасёнными; безусловный
  индикатор соединения убран. Профиль показывает фактическую сборку APK.
- Повтор входа ограничен одной попыткой после явного 502/503/504. Неизвестный
  результат запроса не порождает многократные автоматические входы.
- Сборщик веб-кабинета включает каталог `soc/` с изображениями.
- Страница установки содержит явный вход в SOC **того же сервера**, что APK.
  Отдельная комната жюри обозначена как другой набор данных.

## Реально проверенный публичный путь

API: `https://saq-bol-mobile.onrender.com`.
Кабинет сотрудника: `https://saq-bol-mobile.onrender.com/soc/`.
Роль определяется сервером после входа; адрес `/soc/` не выдаёт полномочия.

Все три существующих аккаунта успешно прошли login endpoint с правильными
ролями. Пароли не менялись. Клиент получил 403 на SOC API.

На Honor X6 установлен первый переданный SOC APK; его SHA-256 совпал с
файлом команды. Через его интерфейс выбран учебный Алексей, сумма 900 000 ₸
и отмечено, что перевод диктуют по телефону. После подтверждения сервер
создал `28e43557-b7b6-4584-8397-e3e8104f9944`, статус `cooling_off`.
Баланс не уменьшился. Эта же квитанция открылась в публичном браузерном
кабинете сотрудника и клиента; перезагрузка восстановила обе сессии.
USB использовался для управления WebView, а запросы шли к публичному HTTPS.
`adb reverse` отсутствует. Затем последний `(1).apk` установлен через
`adb install -r` успешно, без удаления данных.

Отдельный серверный контроль создал только одну операцию
`21ceaa3d-0628-434e-a5a0-803dba059eb9`: Cooling-Off, одна запись SOC,
неизменный баланс и сохранность ранее наблюдавшейся истории.
Это дополнительная API-проверка, не второй физический телефон.

## Ограничения

- Публичный backend сейчас использует временное хранилище и Telegram
  `fake_enabled`. В этой проверке настоящие Telegram-сообщения не отправлялись.
- Backend не перезапускался и не развёртывался заново ради дизайна. Новые
  серверные Guardian review/timeout из зависимой ветки нельзя объявлять
  опубликованными только по успешной сборке Android.
- Новый дизайн веб-кабинета подготовлен исходниками, но его размещение на
  Render требует сначала решения сохранности текущей базы. Обновление
  Cloudflare страницы загрузки не обновляет backend Render.
- Большая сумма сама по себе не гарантирует паузу. В воспроизводимом примере
  используются также признаки звонка и выбранный учебный получатель.
- CI раньше не запускался из-за биллингового ограничения GitHub; локальные
  PASS не считаются успешно прошедшим GitHub CI.
- Финальная установка релизного build 23 и проверка опубликованных байтов
  должны быть подтверждены отдельным release evidence, а не этим планом.

## Питч: телефон → ноутбук

1. Открыть APK клиентом, на ноутбуке открыть **SOC для этого APK** со страницы
   загрузки и войти сотрудником. Не использовать отдельную комнату жюри.
2. На телефоне выбрать учебного Алексея, 900 000 ₸ и отметить диктовку по
   телефону. Проверить реквизиты и подтвердить один раз.
3. Открыть квитанцию; найти её полный ID в ленте SOC. Показать причины
   решения, затем граф и операции по выбранной связи.
4. Показать тот же ID, состояние проверки и неизменный клиентский баланс.
   Не утверждать, что сотрудник одобрил платёж, если выполнен лишь просмотр.

Main не изменяется. Изменения подготовлены отдельной зависимой веткой к
командному review; объединение остаётся за владельцем.
