# Saq Bol — производительность (замер 19 ноября 2026)

Ядро скоринга отвечает за **≈1 мс (p95 1,06 мс)**. Полный запрос «браузер-сервер →
FastAPI → PostgreSQL → Redis → ответ» при одном клиенте — **p95 23,5 мс, p99 27,7 мс,
0 ошибок** на 1000 запросах. Под нагрузкой в 8–16 параллельных клиентов задержка растёт
из-за очереди в одном процессе uvicorn, ошибок по-прежнему нет.

Это измерения прототипа на синтетических данных, а не обещание для продакшена банка.

## Окружение

Одна машина для всех замеров:

| Что | Значение |
|---|---|
| CPU / память | Intel Xeon 2,30 ГГц, 4 ядра · 15 ГБ |
| Python | 3.12.3, один процесс `uvicorn app.main:app` (без `--workers`) |
| PostgreSQL | 16.15, локально, пустая база → `alembic upgrade head` → `scripts.seed_bcc` (299 счетов, 6116 операций после замеров) |
| Redis | 7.0.15, локально, без сохранения на диск |
| Лимит запросов | `BCC_REQUEST_RATE_LIMIT_PER_MINUTE=10000` (максимум настройки) — иначе замер упирается в защитный лимит 120/мин |

## Только ядро (engine-only)

`uv run python -m scripts.benchmark_antifraud --redis-url redis://localhost:56379/2`

500 оценок после 30 прогревочных. Входит: поведенческие правила, счётчики скорости в Redis,
граф NetworkX, ML-модель. Не входит: HTTP, PostgreSQL.

| Метрика | Реальный Redis | fakeredis |
|---|---|---|
| ML p95 | 0,06 мс | 0,05 мс |
| Ядро p50 | 0,93 мс | 1,06 мс |
| Ядро p95 | 1,06 мс | 1,15 мс |
| Ядро p99 | 1,17 мс | 1,24 мс |

Исключение внутри ядра прерывает замер целиком, поэтому доля ошибок здесь — 0.

## HTTP + PostgreSQL + Redis

`uv run python -m scripts.benchmark_http --base-url http://localhost:8765 --requests 1000 --concurrency N --accounts accounts.json`

Каждый запрос — `POST /api/v1/transfers/evaluate` с новым `request_id`, решение
сохраняется в PostgreSQL. Трафик: 80 % обычных переводов между 200 засеянными счетами,
10 % пресет социальной инженерии, 10 % пресет дроппер-хаба. 30 прогревочных запросов не
считаются. Время — от отправки до полного ответа на стороне клиента.

| Параллельных клиентов | p50 | p95 | p99 | max | Ошибки | Пропускная способность |
|---|---|---|---|---|---|---|
| 1 | 15,8 мс | 23,5 мс | 27,7 мс | 110 мс | 0 из 1000 | 59 запросов/с |
| 8 | 97,9 мс | 168,7 мс | 198,6 мс | 295 мс | 0 из 1000 | 77 запросов/с |
| 16 | 226,1 мс | 360,9 мс | 467,2 мс | 508 мс | 0 из 1000 | 68 запросов/с |

Решения соответствуют сценариям: все запросы хаба — `blocked`, социальной инженерии —
`cooling_off`, обычные — в основном `approved`; часть обычных уходит на удержание, потому
что одни и те же отправители повторяются и срабатывает сигнал всплеска операций.

## Что видно из замеров

- **Узкое место — один процесс, а не скоринг.** Ядро занимает около 1 мс из 16 мс; остальное —
  HTTP, запись в PostgreSQL и сериализация. Рост задержки при 8–16 клиентах — очередь к
  одному процессу; пропускная способность почти не растёт. Для пилота: несколько процессов
  за балансировщиком, общий Redis и PostgreSQL.
- **Защитный предел срабатывает правильно.** Если один счёт превышает 512 записей в окне
  скоринга, сервер отвечает `503` с `Retry-After: 60` и не выносит решение по неполной
  истории (fail-closed). Первая попытка замера с одним отправителем упёрлась именно в это,
  поэтому нагрузка распределена по счетам.
- **Лимит 120 запросов в минуту** на клиента включён по умолчанию: при замере без его
  повышения 84 % запросов получили `429`.

## Как повторить

```bash
cd backend
export BCC_DATABASE_URL="postgresql+asyncpg://USER@/DB?host=/tmp&port=PORT"
export BCC_REDIS_URL=redis://localhost:6379/0 BCC_API_KEY=... BCC_SOC_API_KEY=...
export BCC_REQUEST_RATE_LIMIT_PER_MINUTE=10000
uv run alembic upgrade head && uv run python -m scripts.seed_bcc
uv run uvicorn app.main:app --port 8765 &
uv run python -m scripts.benchmark_antifraud --redis-url "$BCC_REDIS_URL"
uv run python -m scripts.benchmark_http --base-url http://localhost:8765 --concurrency 1 --accounts accounts.json
```

`accounts.json` — список `{"id", "phone"}` засеянных счетов, например:
`psql ... -Atc "select json_agg(json_build_object('id',id,'phone',phone)) from (select id, phone from accounts limit 200) a"`.
Не запускайте HTTP-замер на базе живого демо: каждый запрос сохраняется.
