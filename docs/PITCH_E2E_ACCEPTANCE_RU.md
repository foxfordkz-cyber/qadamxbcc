## Подтверждённые факты до расширения экосистемы

На физическом Honor X6 создан синтетический перевод 900 000 ₸ во время звонка:
`28e43557-b7b6-4584-8397-e3e8104f9944`. Сервер вернул `cooling_off`.
Баланс остался 4 785 900 ₸. Та же операция открыта клиентом и SOC в публичном
web-кабинете mobile, проверено восстановление после reload. Это реальный публичный
HTTPS, без adb reverse. Это доказывает телефон → backend → SOC, но ещё не полный
круг с живым Telegram и решением сотрудника обратно на телефон.

Подписанный `.demo` build 23 установлен поверх прежней версии на Honor, SHA-256
`8b729346c8f40ebdf3feaa04196d6c540d92bd429e7e9dd6fbcea2578ff1c136` совпал с
файлом на устройстве. Клиентская сессия сохранена. Последующие изменения протокола и
polling готовятся отдельно: их нельзя приписывать этому APK.

## Сценарий на три минуты

1. 0:00–0:30: клиент на телефоне показывает учебный баланс и получателя.
2. 0:30–1:00: вводит 900 000 ₸, подтверждает признак звонка, отправляет один раз;
   показывает серверный статус и transaction ID.
3. 1:00–1:30: доверенное лицо получает заранее согласованное уведомление и сообщает
   подозрение. При fake-адаптере явно назвать этот шаг имитацией, не живой доставкой.
4. 1:30–2:20: SOC того же mobile backend показывает ID, сумму, дело и событие;
   сотрудник выбирает допустимое решение. Platform Admin для этого не используется.
5. 2:20–3:00: телефон автоматически перечитывает статус, показывает квитанцию и баланс.
   Зафиксировать transaction ID и case ID в начале/конце записи.

Перед демонстрацией проверить, что сайт открывает mobile SOC, а не отдельную jury room.
Действие контакта не должно самостоятельно списывать деньги. Повтор идемпотентного
запроса проверять автоматическим тестом, не повторными нажатиями с новым ключом.

## Блокеры и условия GO

Публичный mobile — временная БД и fake Telegram; полный persistence/live-E2E GO не выдан.
Не делать restart/deploy до сохранения всей фактической базы и проверки restore.
Новая live-сессия требует отдельного согласия тестового контакта. Старые согласования
ограниченных завершённых сессий не являются бессрочным разрешением на сообщения.
Локальные результаты и прежние отчёты не заменяют текущую проверку публичного сервера.
