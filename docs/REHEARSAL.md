# Репетиция Saq Bol

Это рабочий сценарий команды на три минуты, а не подтверждённый регламент организаторов.
Данные и суммы синтетические; `approved` не выполняет банковскую проводку.

## Проверка перед показом

1. Выполнить `verify.sh` или `verify.ps1` и получить код `0`.
2. Из `backend/` выполнить:

   ```bash
   uv run python -m scripts.rehearse_demo --output ../.local-checks/rehearsal-proof.json
   ```

   Выбрать новое имя отчёта для повторного запуска. Скрипт не принимает URL работающей
   системы: он создаёт временную SQLite-базу, запускает настоящий FastAPI, ML и граф
   через ASGI и удаляет только свою временную базу после проверки. Используется fakeredis.
   Отчёт включает отдельные решения, причины, contributors, графовые/velocity признаки
   и результаты проверок. Код `1` или `success: false` означает неготовность сценария.

3. Из корня репозитория на Windows выполнить:

   ```powershell
   .\scripts\start-local-demo.ps1 -FreshRehearsal -NoBuild
   ```

   Открыть напечатанный URL. `-NoBuild` требует готовый production build; для первой
   подготовки запустить без этого флага. Backend проверяется через `/ready`, включая
   БД, Redis и ML, прежде чем launcher объявляет запуск готовым. Свободные порты
   выбираются автоматически; существующие приложения не останавливаются.

4. Показать три пресета в указанном ниже порядке. Для следующей полноценной репетиции
   лучше создать новый запуск, чем накапливать сотни попыток в одной истории.

Каждая репетиция получает новую базу `.local-checks/rehearsals/<run-id>.db`.
`--fresh` использует исключительное создание и отказывается открывать существующий файл.
Пути CLI ограничены `.local-checks/`. Обычный запуск без `-FreshRehearsal` продолжает
использовать сохранённую `.local-checks/local-demo.db`.

JSON-запись `.local-checks/local-demo-<run-id>.json` содержит URL, PID, выбранную базу
и пути логов. Запуски не завершают предыдущие процессы автоматически. Освобождать
ресурсы нужно только у конкретного законченного запуска, сверив его запись и процессы.
Не завершать Docker Desktop или чужие сервисы ради репетиции.

Если порты заданы вручную через `-FrontendPort` / `-BackendPort`, открыть отдельный
профиль браузера: на старом origin могут остаться ID незавершённых операций из прежней
базы. Не стирать их автоматически ради красивого показа. При случайном совпадении
нового origin с прежней репетицией также использовать отдельный профиль.

## Рабочий сценарий: 180 секунд

| Время | Действие | Что доказываем |
| --- | --- | --- |
| 0:00–0:30 | Нажать «Обычный перевод»; показать решение и время скорера. | Легитимный перевод проходит. ML-score и конечное решение — разные величины. |
| 0:30–1:15 | Нажать «Социальная инженерия»; показать сочетание звонка и депозита, предупреждение и таймер. Переключить ҚАЗ/РУС в окне. | Объяснение связано с конкретными сигналами; клиент получает паузу и понятный следующий шаг. |
| 1:15–1:35 | Оставить перевод удержанным либо явно отменить. Не ждать 15 минут и не ускорять часы. | Сервер удерживает операцию; закрытие окна не означает отправку денег. |
| 1:35–2:25 | Нажать «Дропперский хаб»; показать SOC, узел получателя, 12 входящих связей, транзит и общие устройства. | Решение опирается на движение денег и граф, а не только на признаки жертвы. |
| 2:25–2:45 | Показать ML contributors и объяснения правил рядом с графом. | Решение можно разобрать и проверить. Contributors — tree-path contributions, не SHAP. |
| 2:45–3:00 | Открыть предложение shadow-пилота. | Понятен следующий шаг: измерение качества на данных банка без влияния на деньги. |

Для вопросов жюри доступна расширенная демонстрация: вставка реквизитов в поле при
активном переключателе звонка показывает настоящий browser paste event. Автоматический
preflight проверяет принятие этого API-сигнала, но не заменяет проверку событий браузера.

## Если инфраструктура недоступна

- При недоступном Docker использовать локальный runner: он исполняет реальный код
  rules/graph/ML с SQLite и fakeredis. Чётко назвать эту конфигурацию.
- Не выдавать встроенный Next-only demo за работающий ML backend. В local runner
  frontend использует `BCC_API_MODE=live` и настоящий FastAPI.
- Не показывать измерения fakeredis как производительность Redis/PostgreSQL.
  JSON preflight подтверждает функциональность, а не p95, RPS или банковскую масштабируемость.
- При ошибке сверить stderr из записи запуска. Перезапуск на новой базе не должен
  маскировать функциональное падение: сначала проверить preflight и объяснить проблему.
- После длительной паузы перед показом запустить новую изолированную репетицию:
  velocity-окна и графовые причины зависят от времени.

## Linux/macOS

Preflight одинаков на всех ОС: `uv run python -m scripts.rehearse_demo` из `backend/`.
Для интерактивного backend можно выбрать новое имя базы в demo state directory:

```bash
uv run python -m scripts.run_local_demo --database ../.local-checks/rehearsals/stage-01.db --fresh --port 8000
```

В другом терминале запустить frontend с переменными `BCC_API_MODE=live`,
`BCC_API_URL=http://127.0.0.1:8000` и четырьмя seeded IDs/телефонами из
`docker-compose.yml`. Для последующих запусков выбирать новое имя файла либо убрать
`--fresh`, чтобы продолжить именно эту репетицию. Профиль `pilot` для этого runner запрещён.
