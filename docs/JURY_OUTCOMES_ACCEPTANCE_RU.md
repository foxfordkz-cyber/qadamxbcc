# Saq Bol · проверка сценариев жюри

Все суммы и операции в этом показе учебные. Сборка APK, QR и публикация стенда имеют отдельный цикл выпуска.

## Два решения при одинаковой сумме

На сервисе жюри откройте `/jury`, затем «Неге тоқтады?». В разделе «Бронь на маркетплейсе» нажмите «Проверить оба перевода». В обеих историях перевод составляет 96 000 ₸. Два часа назад этот получатель получил 1 200 ₸. Во второй истории покупатель сообщил, что его попросили сделать именно этот перевод по телефону.

Кнопка отправляет `POST /jury/results/pair`. Сервер заново оценивает обе стороны пары `market-reservation` существующим антифрод-движком. У каждой стороны своя изолированная история. Движок возвращает решение и причины на двух языках. На этой версии обычная покупка одобрена, покупка по просьбе звонящего поставлена на паузу. Обе проверки можно повторить. [Экран сравнения](../reports/jury-pair.png)

## Что означают 57, 3 и 4

В банковской аналитике и на `GET /jury/results` нажмите на число, чтобы открыть конкретные записи. В наборе 120 размеченных синтетических переводов, из них 60 мошеннических и 60 обычных. Система поставила на паузу или заблокировала 57 мошеннических переводов, пропустила 3 и задержала 4 обычных платежа. Пауза означает вмешательство в момент оценки. Расчёт использует решение для каждого отдельного сценария.

Откройте «Лишние задержки», выберите пример и посмотрите его ID и сработавшие признаки. Полный набор и сводку воспроизводит `python -m scripts.scenario_stand --write` из каталога `backend`. [Экран банка](../reports/jury-bank.png) · [Данные 120 сценариев](evidence/scenario_stand.json)

## Пересмотр обычного платежа

1. В синтетическом кошельке отправьте 40 000 ₸ новому получателю и при проверке укажите, что сейчас говорите по телефону. Откройте квитанцию перевода в состоянии Cooling-Off.
2. Нажмите «Это мой перевод · запросить проверку». Открывается квитанция обращения. При возвращении к операции кнопка открывает уже созданное дело и переписку.
3. В SOC откройте это дело, возьмите в работу и задайте вопрос о звонке. Ответьте из клиентского обращения. Закройте дело с результатом «Законный перевод».
4. Клиент видит итог рассмотрения. Для разрешённого перевода остаются обязательными условия исходной политики, включая окончание паузы и ответы клиента. Повторная отправка подтверждения сохраняет одно списание.

## Если доверенный человек молчит

У включённого шлюза наблюдатель проверяет ожидающие уведомления каждые 15 секунд. Используется серверный срок подтверждения семьи, а при его отсутствии — срок уведомления. После истечения ожидания дело появляется в обычной очереди SOC. Для перевода, требующего согласия семьи, отметка «получено» сама по себе не подтверждает условия перевода. Сообщение о подозрении ставит дело в очередь без ожидания срока.

Одна операция получает одно дело пересмотра при конкурирующих запросах клиента и повторных проходах наблюдателя. При остановке шлюза очередь восстанавливается из записей БД в пределах семидневного окна хранения. Шлюз сохраняет основание открытия дела и ID исходной операции. Уведомление, открытие и закрытие дела сами по себе не списывают деньги.

## Непрерывная съёмка на двух телефонах

Этот приёмочный прогон требует сборки с изменениями, тестового сервера с реальным Telegram worker и участника, давшего согласие на конкретный тест. Публичная комната жюри использует имитацию контакта. Для съёмки подготовьте отдельный синтетический кошелёк и согласованный чат.

| Кадр | Что показать одним дублем |
|---|---|
| 1. Клиент | На первом телефоне показать баланс до операции. Отправить учебный перевод с включённым семейным подтверждением. Показать Cooling-Off и номер операции в квитанции. |
| 2. Контакт | На втором телефоне открыть реальное входящее сообщение Telegram и нажать «Есть подозрение». |
| 3. Банк | В SOC открыть автоматически появившееся дело по этой операции, проверить основание и закрыть с исходом «Мошенничество подтверждено». |
| 4. Клиент | На первом телефоне открыть связанное обращение, показать результат сотрудника, тот же номер операции и конечный баланс. Сравнить его с первым кадром. |

Запись принята, когда все четыре кадра видны в одном непрерывном видео. Здесь приложены скриншоты браузера. Автотест этапов 1–4 использует тестовый Telegram-адаптер.

## Локальная проверка

- Сервер жюри использует команду `python -m scripts.jury_wallet` в контейнере из `deploy/render-jury-free.yaml`. Для локального запуска с прежними учебными хешами выполните `docker compose -f docker-compose.jury.yml build wallet`, затем `docker compose -f docker-compose.jury.yml run --rm --service-ports wallet python -m scripts.jury_wallet`. Адрес результатов — `http://127.0.0.1:18002/jury/results`.
- Из `backend` запустите `python -m pytest tests/test_jury_hold_review.py tests/test_second_confirmation.py tests/test_jury_rooms.py`. В проверке таймаута тест переносит срок своей синтетической записи в прошлое. Отсчёт времени общего стенда остаётся штатным.
- Из `android-app` запустите `npm test` и `npx playwright test audit.spec.mjs -g "held receipt"`. Браузерная проверка открывает обращение из квитанции, возвращается и повторно открывает ту же переписку.
