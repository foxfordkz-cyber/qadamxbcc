# Private Scam Check — контракт Бекзата

Дополнение к PR #15; отдельная ветка `feature/bekzat-private-scam-check`.
Это локальная образовательная проверка текста RU/KK, а не обученная модель,
антифрод-решение или новый механизм блокировки. Scoring, Redis velocity, граф,
миграции и финансовые API не изменяются. Существующий `/check` с пятью вопросами сохранён.

## API для Айданы и SOC

`POST /api/v1/integrations/guardian/scam-check`

Требуются включённые demo integrations и действующий operator-issued bearer capability
с ролью `owner` или `soc`. `simulator` запрещён. В pilot маршрут закрыт.
Используйте существующий доверенный backend/BFF для выдачи/передачи capabilities:
подписывающий ключ не должен попасть в браузер. Telegram ID не является owner identity.

```json
{"text":"Ақшаны қауіпсіз шотқа аударыңыз.","language":"kk"}
```

- `text`: непустая строка, максимум 2000 символов; только описание без персональных данных.
- `language`: `ru` или `kk`; язык ответа, правила проверяют оба языка.
- Дополнительные поля, включая `transaction_id`, запрещены.
- Никаких URL fetch, вложений, скачивания файлов, внешнего AI или фоновой очереди.

Ответ `ScamCheckResult` содержит `ruleset_version`, `language`, `advisory_only=true`,
`status`, `signals[{code,explanation}]`, `guidance`, `limitation`, `privacy`.
В нём нет исходного текста, цитат, имени отправителя, chat ID, реквизитов и вероятности fraud.
Все объяснения — фиксированные локализованные строки.

| status | Отображение |
|---|---|
| `signals_detected` | Показать найденные признаки и безопасные следующие действия |
| `no_known_signals` | Эти правила не нашли признаки; безопасность не доказана |
| `insufficient_context` | Неоднозначный/короткий контекст; вывод о безопасности невозможен |

Не отображать последние два состояния зелёным «безопасно» и не разрешать/отменять перевод
на основании результата. Кнопка обращения ведёт в существующий отдельный workflow;
анализ не создаёт SOC incident и не переносит туда введённый текст автоматически.

Коды сигналов: `safe_account`, `credentials`, `remote_access`, `secrecy`,
`impersonation`, `advance_fee`. Число сигналов не является risk score.

| HTTP | Действие клиента |
|---|---|
| 200 | Отобразить типизированный результат, включая limitation |
| 401 / 403 | Обновить разрешённую сессию / показать отсутствие доступа |
| 422 | `{"detail":"invalid_scam_check_request"}`; исправить ввод; он не отражается в ошибке |
| 408 / 413 | Слишком медленный/большой запрос по общим ограничениям API |
| 429 | Уважать `Retry-After`; не запускать цикл фоновых повторов |
| 503 | Интеграции выключены, недоступен limiter или используется pilot; не выдавать вывод |

Успех и ошибки маршрута имеют `Cache-Control: no-store`. POST не меняет состояние;
повтор по действию пользователя безопасен, но использует общую квоту integrations.
Не сохранять текст в localStorage, аналитике, trace attributes, session replay или журнале BFF.
Рендерить фиксированные строки как plain text. Не логировать bearer header.

Проверяемые RU/KK примеры находятся в [api_examples.json](../integrations/api_examples.json),
схемы — в [openapi.json](../integrations/openapi.json), строки — в
[ui_texts.json](../integrations/ui_texts.json), раздел `scam_check`.
Обновление: `cd backend && uv run python -m scripts.export_integration_contracts`.

## Telegram

Новая команда `/scan` и кнопка «Проверить текст / Мәтінді тексеру» открывают отдельное
ожидание одного сообщения. Бот объясняет обработку до ввода. Только private chat,
совпадающий sender, прежняя allowlist и Redis quota. Никаких новых получателей.

FSM хранит только язык и время окончания ожидания (15 минут), без исходного текста или
результата. `/cancel`, `/menu`, смена раздела, успешная обработка и истечение времени
закрывают этот шаг. Исходный текст не цитируется в ответе. Вложения не скачиваются.
Текст анализируется общим с API модулем, а не второй копией правил.

Telegram самостоятельно хранит переписку: «не сохраняется» относится к БД/FSM приложения.
Передача сообщения Telegram уже произошла до вызова нашего обработчика.
В этом этапе live polling не запускался и новых реальных сообщений не отправлялось.
Проверки диспетчера используют подменённый транспорт, отдельно от Docker fake worker.

## Граница конфиденциальности

Перед правилами создаётся временная рабочая копия: NFKC/case normalization, удаление
невидимых format characters, ограниченная нормализация похожих букв, маскирование
URL, email, IBAN-подобных строк, длинных номеров и явно помеченных секретов.
Возвращаются только категории/количество маскированных фрагментов.

Это best-effort masking, не сертифицированный DLP и не гарантированная анонимизация:
имена, адреса, неизвестные форматы секретов могут не распознаваться. Поэтому даже
маскированная рабочая копия не покидает процесс и не возвращается клиенту.
Нет внешнего AI fallback, telemetry с текстом или записи текста в audit/SQL/Redis.
Память процесса не является защищённым хранилищем с гарантированным стиранием.
Утечки через сторонний reverse proxy/APM требуют отдельной проверки при подключении.

Ошибки Pydantic скрывают `input` в строковом представлении. Отдельный APIRoute убирает
FastAPI validation echo, включая неверный JSON и неизвестные поля, не меняя core handlers.
Существующий общий body limit применяется до JSON parsing; Redis outage закрывает доступ.

## QA и пределы

[QA protocol](../qa/SCAM_CHECK_EVALUATION.md) и
[машиночитаемый отчёт](../qa/scam-check-evaluation.json) показывают TP/FP/FN/TN,
precision/recall/FPR, неоднозначные ответы и IDs ошибок. Никаких банковских данных.
Сарказм, пересказ, новые схемы и имплицитное давление могут быть поняты неправильно.
Отрицания обрабатываются ограниченно; проверка никогда не гарантирует отсутствие угрозы.

Для локального demo разрешён только fake/synthetic сценарий. Frontend-приёмка, native
language review, live Telegram нового `/scan` и разрешение владельца на merge — отдельно.
