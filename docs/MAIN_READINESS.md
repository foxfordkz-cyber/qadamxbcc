## Сеть ловушек: проверка новой функции

Добавлены core SOC `GET` / `POST /api/v1/soc/recipients/{account_id}/flag` и
`alerts_only=true` для ленты. Пометка и аудит сохраняются в БД, граф подхватывает
сохранённые версии, следующий перевод другого отправителя получает
`RECIPIENT_FLAGGED`. Скоринг использует доверенный SQL-снимок флага, чтобы устаревший
граф после rebuild не отменил решение оператора. Сохранённые решения автоматически
не пересчитываются, но подтверждение удержанного перевода заново проверяет флаг:
при новой пометке чистая анкета, в том числе до конца таймера, даёт `blocked` и
`RECIPIENT_FLAGGED_AT_RELEASE`. Снятие пометки не возобновляет уже заблокированный
перевод. В браузерном
контракте обязательны причина, request UUID и ожидаемая версия. Аудит различает
сервисный ключ, а не утверждает личность аналитика; банковский SSO остаётся условием
пилота. Полный контракт — [API_CONTRACTS.md](API_CONTRACTS.md).

## Что реализовано вместо прежнего TODO

- SOC-кейсы, действия, история, Timeline, Health, граф и rule/ML inspector подключены
  к API через ограниченный BFF. `expected_version` защищает действия двух операторов;
  после `409` браузер перечитывает данные и требует явного подтверждения.
- Перезагрузка сохраняет выбор кейса и безопасные фильтры, не сохраняет capability,
  тексты заметок или ключи. SOC не открывает чужую мобильную анкету; `/mobile`
  восстанавливает собственное удержание.
- Общий бюджет SOC-интеграций учитывает `429`/`Retry-After`; кейсы опрашиваются раз
  в минуту, Timeline/Health — вручную. Основная transfer feed отделена от capability API.
- Для репетиции `scripts/start-local-demo.ps1 -FreshRehearsal -SocDemo` выдаёт
  серверную SOC-сессию не более часа, подготавливает синтетические связанные кейсы
  и привязывает сервисы к loopback. Telegram — FAKE, gateway — MOCK.
- [Контракты](API_CONTRACTS.md) генерируются из текущего OpenAPI с тестом на drift;
  индекс содержит core, cooling, call-check, SOC, BFF, Zod, доступ и ошибки.
- Слайды пользователь готовит самостоятельно. Существующие PPTX, `/pitch` и
  черновик выступления в этой работе не обновлялись; их актуальность не является
  результатом текущих технических проверок.
