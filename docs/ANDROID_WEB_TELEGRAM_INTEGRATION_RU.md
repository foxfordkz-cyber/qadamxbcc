# Android, Web, Telegram: точки интеграции

## Общий путь

1. Клиент входит через `/mobile/v1/auth/login`. Сервер возвращает роль и субъект.
2. `Gateway` обслуживает account, операции, квитанции, Guardian, кейсы и аналитику.
   Android хранит сессию через существующий DeviceVault; web использует серверную
   cookie. Метаданные web-сессии в storage не дают самостоятельных прав.
3. Перевод проходит действующие core-правила. UUID операции используется далее без замены.
4. После согласия и применимой политики durable worker отправляет уведомление.
5. Подписанный callback проверяется на участника, срок, согласие и повтор.
6. SOC читает сохранённое дело, принимает разрешённое решение с проверкой версии.
7. Клиент перечитывает серверную операцию и показывает фактическую квитанцию.

## Обновление экранов

`connected.mjs` использует существующий polling: активные кошелёк, SOC и квитанция —
3 секунды, списки дел/контактов — 15 секунд, аналитика и timeline — 60 секунд.
Во время ввода, фонового состояния и незавершённого чтения обновление не перерисовывает
форму. Ответ привязан к gateway, текущему экрану и revision: результат старого аккаунта
не попадает в новый. При чтении дела проверяется версия, а не только изменение callback.

`poll-backoff.mjs` увеличивает задержку при ошибке от 3 до 60 секунд; 429 соблюдает
Retry-After. Событие `online` восстанавливает чтение, не обходит Retry-After.
Ошибка показывает, что данные устарели; успешное чтение убирает сообщение.
Повтор polling не повторяет POST перевода. Неизвестный результат мутации разрешается
существующим поиском по idempotency key, не новой операцией.

## Добавление функции

- Сначала проверить существующий endpoint и серверные права.
- Добавить вызов в общий Gateway/feature-module, сохранить ID и серверный статус.
- Использовать существующие локализацию, design tokens и dark/light стили Айданы.
- Добавить контрактный тест, сценарий сетевой ошибки, смены аккаунта и повторного действия.
- Для Telegram расширить существующий handler/service и audit; не пересылать банковские
  секреты и не ставить Bot token в APK. Тесты по умолчанию используют Fake Adapter.

## Диагностика

Различать 401 (данные входа или истёкшая сессия по контексту), 403 (роль), сетевой
сбой, 5xx (сервис) и 426 (обновить приложение). Сопоставлять transaction ID, case ID,
audit и receipt. Технические метрики доступны Platform Admin; private health/config
не публикуются клиенту. `/mobile/v1/compatibility` раскрывает только версию протокола,
минимальный build, словарь статусов и фиксированную страницу обновления.

Публичный mobile сейчас использует fake Telegram. Наличие Telegram-ссылки, успешный
callback через fake или API 200 не доказывают доставку живому контакту.
