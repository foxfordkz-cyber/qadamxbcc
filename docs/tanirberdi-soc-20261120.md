# Часть Танирберді: SOC и восстановление

Рабочая ветка: `codex/tanirberdi-soc-recovery-20261120`, создана от актуального на момент начала `origin/main` (`f4f30ed`). Область работы взята из предоставленного командного плана Saq Bol v2. Существующий мобильный интерфейс, API антифрода и интеграции команды сохранены.

## Что подключено

- В SOC добавлен раздел «Кейсы SOC»: сохранённые обращения, общая аналитика, фильтры по статусу, оператору и дате, курсорная пагинация. API списка принимает только `limit/cursor`, поэтому интерфейс явно сообщает, что фильтры применяются к загруженным кейсам. Сводные KPI поступают отдельно из `/analytics`.
- Карточка кейса читает текущее состояние, историю, заметки, ответы клиента и evidence. Оператор может назначить ответственного, сменить категорию/статус, добавить заметку, запросить уточнение и открыть кейс по ID существующего синтетического сообщения.
- Каждая запись проходит предварительный просмотр и отдельное подтверждение. Используются серверная версия и `Idempotency-Key`. При `409 case_version_conflict` данные перечитываются; повтор требует нового подтверждения. Неопределённый исход не вызывает автоматического повтора: доступен только исходный запрос с исходным ключом.
- Выбранные вкладка, кейс, фильтры и глубина графа восстанавливаются из sessionStorage. Содержимое заметок, токены и финансовые снимки туда не добавляются. Незавершённая запись оставляет только маркер: после перезагрузки требуется сверить серверную историю.
- Evidence связывает кейс с переводом. Граф центрирован на получателе этого перевода, получатель выделен рамкой. Кейсы без связанного перевода не наследуют граф и хронологию другого кейса.
- Хронология читает `/integrations/soc/transactions/{id}/timeline`, сохраняет единый `as_of` при пагинации, показывает сохранённые события ядра, контакта и шлюза на выбранном языке. Просроченный курсор требует обновления снимка.
- Сводка `/summary` и `/health/details` показывают фактические состояния интеграций. Неизвестная очередь остаётся неизвестной; режим Telegram TEST не выдаётся за успешную доставку. Результаты шлюза явно помечены MOCK; просроченные и неподтверждённые результаты не представлены как актуальные.
- Интеграционные факты обновляются вручную; список кейсов обновляется редко и только на видимой странице. Это учитывает общий лимит capability. При `429` используется `Retry-After`.

## Границы демонстрации

SOC BFF предназначен для локального демо: Next должен слушать **127.0.0.1**. Capability оператора находится только в серверном окружении, имеет ограниченный срок и проверяется backend. Проверки Host/Origin не заменяют банковскую аутентификацию. Публичный сайт, статический экспорт, LAN-режим и pilot не получают этот локальный SOC-доступ.

«Рассмотрение завершено» не означает возврат денег. Действия кейса не меняют решение ядра о переводе. Запрос уточнения сохраняется в существующем API-канале клиента; он не обещает отправку вопроса через Telegram. Шлюз MOCK не подключён к реальной базе Национального Банка.

Локальная репетиция использует синтетические счета, отдельную SQLite-базу, in-process Redis и FAKE-адаптер Telegram. Реальные сообщения и внешние проверки не выполняются. У доверенного контакта нет права привязать собственное сообщение к чужой транзакции: связанный SOC-кейс открывается по сообщению владельца; событие подозрения контакта показывается в хронологии той же операции.

## Проверки

Результаты финальных проверок будут записаны после прогона актуальной ветки. Browser harness `frontend/scripts/qa-soc-cases.cjs` проверяет интерфейс с перехваченными API; такой прогон не заменяет проверку настоящего backend и BFF.
