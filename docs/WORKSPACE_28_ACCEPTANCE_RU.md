# Saq Bol × BCC · приёмка 2.8 · 21 ноября 2026

## 1. Исходная точка

Honor VNE-LX1 был подключён с разрешённой отладкой. Установленный пакет имел версию 2.7/code 10. Исходный handoff APK имеет SHA-256 `c21a141fd4aa9fed8310fc153ca6de57d3602be12e49c6649856cbba01d281fc`. Мобильная ветка начиналась с `2792c11`; в неё обычным merge включён `main@f98f375`. Приложение использует Capacitor/WebView, статические модули JS, Android Keystore, FastAPI и серверные роли.

* На публичном стенде у клиента была история, но не было связанных обращений и дел SOC. На изолированном PostgreSQL набор wallet-v1 уже существовал. Эти базы имеют разное наполнение.
* В 2.7 главная ждала завершения параллельной группы запросов. Медленный ответ аналитики задерживал уже полученный баланс. Общая блокировка затрагивала навигацию. Новый экран показывает поступающие данные независимо и помечает обновление. Некоторые второстепенные экраны и мутации по-прежнему используют общий индикатор.
* При несовместимом ответе metrics/staff старый экран мог показать один заголовок. Теперь оператор видит ошибку данных и действие для повторной загрузки.
* Ранее у пользователя отсутствовал выбор сохранения сессии, а её предельный срок устанавливал сервер. В 2.8 этот выбор доступен при входе. Срок авторизации остался ограниченным.
* На текущем сервере учётные данные трёх ролей подошли с первой проверенной авторизацией. Для контрольных запросов использованы локальные файлы, привязанные к точному HTTPS origin.

## 6. Сохранение входа

При включённом флажке Android сохраняет сессионный секрет через DeviceVault с ключом Android Keystore. При выключенном держит токен в памяти процесса. Пароль не сохраняется приложением. В браузере авторизацию подтверждает HttpOnly cookie, защищённая Secure/SameSite Strict; локальная метка содержит origin и subject. При выключенном флажке новая версия backend выдаёт сессионную cookie. Это изменение проверено на собственном PostgreSQL-стенде. Публичный сайт работает на более ранней версии. Настройка в профиле ведёт к повторной авторизации.

Каждое восстановление проверяет GET /session. Временная 503 допускает повтор с сохранённой сессией, подтверждённая 401 очищает состояние. Для старого запроса проверяется принадлежность той сессии, в которой его отправили. Срок по умолчанию 1 800 секунд, конфиг допускает 60–3 600. Автопродления нет. Проверены три браузерные роли, опция входа, отсутствие восстановления после отказа в новой вкладке, временная 503 и ответ об истечении. Тест инъекции 401 не измеряет фактическое истечение TTL на Render.
