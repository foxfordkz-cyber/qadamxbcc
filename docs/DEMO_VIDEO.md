## Сценарий защиты

| Время, приблизительно | Что видит зритель |
| --- | --- |
| 0:00 | Клиент выбирает язык и переводит 25 000 ₸ знакомому получателю. Скорер одобряет перевод. |
| 0:15 | Перевод с депозита во время звонка попадает на 15-минутное удержание. После завершения звонка приложение спрашивает, кто начал перевод. |
| 0:40 | Клиент уведомляет доверенное лицо. Локальный имитатор Telegram доставляет запрос и передаёт проверенный ответ «Подозрительно». |
| 1:12 | Даже при чистых ответах сервер блокирует операцию с причиной `TRUSTED_CONTACT_SUSPICION`. |
| 1:28 | Долгое нажатие на кнопку подтверждения включает тихий код. Клиент видит «В обработке», сервер фиксирует `DURESS_SIGNAL` и блокирует перевод. |
| 1:43 | Пресет дроп-счёта приводит в SOC. Видны граф получателя, вклады признаков ML, переключение языка и поток тестовых операций. |
| 2:20 | Сотрудник открывает печатную справку. Номер операции в документе совпадает с номером заблокированного перевода. |

FastAPI, правила, ML, граф, запись решения и проверка ответа доверенного лица выполнялись на локальном сервере. Приложение использовало синтетические счета в отдельной SQLite и fakeredis. Канал доставки явно подписан FAKE. Уведомления обрабатывал локальный воркер с тестовым Telegram-адаптером.

## Воспроизведение сценария

Подготовьте backend через `uv sync --frozen --python 3.12` в папке `backend`. В `frontend` выполните `npm ci`, `npm run build` и `npx playwright install chromium ffmpeg`. Для проверки финального файла нужен FFmpeg с декодером VP8 и выводом PNG. Если он доступен в PATH, переменную `FFMPEG_EXECUTABLE` можно пропустить. Из корня репозитория выполните команды для своей ОС.

```powershell
# Выберите установленные на вашем компьютере Chrome и FFmpeg.
$env:CHROMIUM_EXECUTABLE = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
$env:FFMPEG_EXECUTABLE = "$env:LOCALAPPDATA/ms-playwright/ffmpeg-1011/ffmpeg-win64.exe"
node scripts/record-rehearsal.mjs --output .local-checks/release-film

# Проверка тех же действий во втором браузере с отдельной базой.
$env:CHROMIUM_EXECUTABLE = 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe'
node scripts/record-rehearsal.mjs --quick-check --output .local-checks/release-edge
```

На Linux/macOS путь к FFmpeg можно задать в `FFMPEG_EXECUTABLE`. Если `CHROMIUM_EXECUTABLE` отсутствует, Playwright запускает установленный им Chromium. Скрипт подбирает свободные loopback-порты, создаёт свежую базу в `.local-checks/rehearsals/` и временные служебные ключи в памяти. Режим `--quick-check` выполняет те же операции с отдельной базой и сразу переходит к следующему экрану после проверки результата.

## Что проверено

Google Chrome 158.0.8127.36 записал три пресета и дополнительный перевод с тихим кодом. Microsoft Edge 157.0.4341.60 повторил этот путь на другом наборе синтетических операций. В обоих прогонах проверены ответ доверенного лица, серверная блокировка, вклад признаков модели, граф и идентификатор в печатной справке. В списках ошибок браузера и запросов API — ноль записей. [Прогон Chrome](../deliverables/demo/manifest.json) · [Повтор в Edge](../deliverables/demo/edge-qa.json)

FFmpeg прочитал контейнер и декодировал кадры на 20-й, 53-й, 92-й и 152-й секундах. Оба файла субтитров содержат 11 синхронизированных фрагментов и заканчиваются на отметке 2:42,560. SHA-256 видео и результаты проверки сохранены в отдельном файле. Для повторной сверки выполните `node scripts/verify-demo-film.mjs .local-checks/release-film`. [Проверка видео](../deliverables/demo/verification.json)

Оценки задержки на экране относятся к отдельным синтетическим переводам. Условия и результаты нагрузочных измерений документированы отдельно. [Отчёт о производительности](evidence/role-performance.json)
