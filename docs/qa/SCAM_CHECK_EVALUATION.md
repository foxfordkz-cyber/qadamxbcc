# Scam Check: воспроизводимая проверка

Дата: 2026-11-19. Объект: отдельный offline analyzer, не core scoring.

## Метод

`backend/qa/scam_check_v1.json` — 40 авторских синтетических сообщений, 20 RU и 20 KK;
20 положительных и 20 отрицательных меток. Есть обычная переписка, предупреждения,
контекст в разных предложениях, Unicode-обфускация, отрицания и известные трудные случаи.
RU/KK версии соответствующих ситуаций коррелируют; это не 40 независимых наблюдений.
Дубликаты ID/текста отвергаются загрузчиком. SHA-256 считается по канонизированному JSON,
чтобы CRLF/LF и оформление файла не меняли идентификатор набора.

Это открытая development/challenge panel, созданная вместе с правилами, не слепой holdout.
Набор может использоваться для исправления правил; это прямо исключает заявление об
независимой проверке качества. Обучения, оптимизации порога или cross-validation нет.
Для реального измерения качества QA-команде нужен отдельный размеченный и закрытый
до оценки набор с независимой RU/KK проверкой, согласованной политикой данных и
распределением, соответствующим реальному использованию. Новые реальные данные сюда не загружать.

Два варианта работают на одном наборе и одинаковой маскированной копии:

- `keyword_baseline`: наличие слов из того же словаря, без action/context/negation checks.
- `contextual`: текущие пары «тема + действие», границы предложений/контраста и отрицания.

Это ablation, а не сравнение с Qorgan, BCC360 или банковским продуктом. `insufficient_context`
учитывается как отсутствие обнаружения: нельзя убрать трудные примеры из знаменателя.
Precision = TP/(TP+FP), recall = TP/(TP+FN), FPR = FP/(FP+TN); пустой знаменатель даёт null.
Ошибки выводятся по ID, без текста. Все промежуточные и итоговые показатели вычисляются,
а не вписываются вручную; известные ошибки не скрываются ради «100%».

## Воспроизведение

Из `backend`:

```sh
uv run python -m scripts.evaluate_scam_check --benchmark --output ../.local-checks/scam-check-evaluation.json
uv run pytest tests/test_scam_check.py tests/test_scam_check_evaluation.py tests/integrations/test_scam_check_api.py tests/integrations/test_bot_assistant.py
```

[Зафиксированный результат](scam-check-evaluation.json) содержит версию правил, hash корпуса,
общие метрики, метрики по языкам/ситуациям и ID расхождений. CI вычисляет свежий отчёт
и публикует artifact `scam-check-evaluation`; длительность не является CI pass threshold.
Структурные privacy/access/contract проверки — обязательные тесты.

Latency: 1000 последовательных вызовов после прогрева, nearest-rank p50/p95/p99,
Python/platform в отчёте. Измеряются только локальные правила; это не HTTP + SQL,
Telegram delivery, worker queue или antifraud engine. Нулевые ошибки означают, что
1000 вызовов завершились, а не отсутствие классификационных FP/FN.

[HTTP observation](scam-check-http-latency.json): отдельный запуск Windows → loopback Docker,
один keep-alive клиент, 3 прогревочных и 20 последовательных POST с одним синтетическим
owner capability, без параллелизма и повторов. Всего 23 запроса в пределах существующей
квоты 30/min. Измерение включает HTTP/auth/Redis/rules; SQL в этом маршруте отсутствует.
P99 здесь — максимум маленькой выборки, не устойчивая оценка хвоста. Результат нельзя
сравнивать с engine-only benchmark или выдавать за банковский SLA.

Core QA остаётся в `scripts.evaluate_fraud_model` и `scripts.benchmark_antifraud`.
Не складывать их выборки/latency с этим анализатором. PostgreSQL/Redis, миграции,
Docker-сценарии и browser/frontend regression выполняются отдельно в существующем CI.

## Как использованы № 2, 3, 19 и QA № 7, 20, 21

| Источник | Применённый подход | Граница |
|---|---|---|
| [#2 BCC Shield 360](https://github.com/MaratelloMaJo/bcc-shield-360) | Privacy boundary перед анализом | Свой код маскирования; клиентский demo HMAC и внешний AI не перенесены |
| [#3 Qorgan](https://github.com/Ibrakazah/qorgan) | Offline RU/KK и объяснимые признаки | Новые детерминированные правила; чужая модель/данные и accuracy не заимствованы |
| [#19 Barclays/Aegis](https://github.com/OnkarNanaware/Barclay-s-Hackathon) | Минимизация данных и разделение ответственности | Один модуль в существующем backend, без копирования микросервисной инфраструктуры |
| [#7 Qorgan antifraud](https://github.com/alinaraevali18/qorgan-antifraud) | Baseline и отдельный отчёт о FPR | Одинаковый собственный корпус; результаты чужой команды не выдаются за наши |
| [#20 IBM AMLSim](https://github.com/IBM/AMLSim) | Синтетические сценарии вместо реальных клиентов | Собственная небольшая текстовая panel; AMLSim/JVM не установлены и его прогон не заявляется |
| [#21 Fraud Detection Handbook](https://github.com/Fraud-Detection-Handbook/fraud-detection-handbook) | Раздельные метрики и честные границы оценки | Не переносили код/датасеты; независимого holdout пока нет |

В этот PR не включены исходники, веса, изображения или датасеты указанных репозиториев.
Ссылки — происхождение идей, не заявление об авторстве этих идей. Не заявляется, что
наш проект лучше конкурентов по качеству без сопоставимой общей проверки.
