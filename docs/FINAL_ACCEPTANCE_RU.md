# Приёмка Saq Bol 2.9

## Текущее состояние на 24 ноября 2026

Публичная страница Cloudflare распространяет командный APK 2.9, build 22. Его SHA-256 совпал с файлом, прочитанным с Honor, а пользователь подтвердил build 22 в профиле. Манифесты current.json и team.json указывают на один файл. Последующие разделы сохраняют результаты предыдущих сборок с указанными там ограничениями.

В интеграционную ветку включены дизайн Айданы, все 12 пар сравнительного стенда, пересмотр задержанного перевода, очередь SOC после сигнала или отсутствия ответа контакта и опубликованные манифесты build 22. Исправлен Docker-контекст жюри, который исключал два файла данных, используемых Dockerfile. Проверка этих данных через собранный HTTP-сервис добавлена в CI.

Проверка действующего saq-bol-mobile подтвердила вход client_demo, admin_demo и platform_demo, их серверные роли и доступ к соответствующим API. Клиент получает 403 при запросе SOC. Администратор платформы открывает список сотрудников. История клиента читается. Сервер сообщает ephemeral_store=true. Его текущая история требует резервирования перед заменой процесса.

Изолированная локальная репетиция PostgreSQL и Redis прошла. Проверены импорт SQLite, три решения, два перезапуска API, сохранение сессий и журнала, идемпотентность и полное восстановление PostgreSQL. Это результат локальной тестовой среды. Публичный сервис пока использует временное хранилище.

19 backend-тестов пересмотра, семейного подтверждения и комнат жюри прошли на объединённой ветке. 45 тестов Android прошли. После синхронизации манифестов отдельно повторены 4 проверки упаковки APK. Браузерная проверка открыла переписку из задержанной операции и повторно открыла то же обращение после возврата. Изменения серверных функций подготовлены для review и обновления стенда. Последние проверки GitHub Actions не стартовали из-за сообщения об оплате или лимите расходов владельца.

Docker-образ успешно собран после исправления контекста. В нём прошли 11 тестов журнала жюри и пересмотра, включая реальный Redis с Unix-сокетом, фоновую эскалацию и квитанцию клиента. Часть этих тестов повторяет Windows-прогон. HTTP-проверка запущенного контейнера открыла сводку 120 сценариев и выполнила две пары. SHA-256 упакованного APK совпал с опубликованным build 22. При запуске контейнеров локальный Docker завис, после перезапуска Docker Desktop проверки повторены успешно.

## Что требуется от участника для завершения

1. На открытой странице Render сервиса saq-bol-mobile показать раздел Settings с Instance Type и доступность Shell. Если названия непонятны, передать снимок этой части панели, закрыв вкладки с переменными окружения и секретами. Если Shell доступен, инженер проверяет путь действующей SQLite и переносит полный snapshot в защищённое хранилище до обновления. При отсутствии такого доступа требуется отдельное решение о доступном способе сохранения истории.
2. Владелец GitHub проверяет Billing & licensing, раздел Actions. После устранения ограничения инженер повторяет CI. Техлид проверяет PR #32, затем интеграционный PR #33. Окончательное объединение в main выполняется с разрешения владельца.
3. После обновления тестового backend инженер повторно проверяет вход, сохранность истории и очередь SOC. Участник предоставляет отдельное согласие на новую ограниченную Telegram-сессию в конкретном тестовом чате.
4. На первом телефоне открыть клиентский аккаунт и показать баланс. В разделе защиты подключить согласившийся контакт, дождаться подтверждённого сервером согласия и включить семейную проверку. Второй телефон принадлежит этому контакту. На ноутбуке открыть SOC под admin_demo.
5. По согласованному пресету создать один синтетический перевод. Показать паузу и ID. На втором телефоне дождаться сообщения по той же операции, нажать получение и после проверки журнала нажать подозрение.
6. В SOC открыть дело по этому ID, проверить основание и сохранить результат рассмотрения. На первом телефоне открыть связанное обращение, показать результат, ID исходной операции и баланс. Закрытие дела отражает результат рассмотрения. Финальное состояние перевода определяется существующей политикой Cooling-Off.
7. Одним непрерывным видео записать шаги 4–6. Снять повторное открытие приложения и восстановление клиентской сессии. Для проверки публичного подключения выполнить это по обычному интернету телефона.

Новая двухтелефонная Telegram-проверка и запись этого сценария пока ожидают обновления тестового окружения и согласия участников.

На локальной копии две роли проверили одно обращение на 900 000,25 ₸. После закрытия дела сотрудником клиент получил результат на казахском и русском. Сумма на счёте осталась прежней, сервер продолжал удерживать перевод. Отдельная проверка подтвердила, что клиенту закрыт доступ к выписке получателя из дела SOC.

Во второй комнате проверили семейную защиту через три раздельных сеанса. Клиент включил защиту и запросил перевод на 900 000,25 ₸. Доверенное лицо сверило реквизиты и сообщило о подозрении. При попытке завершить проверку сервер заблокировал перевод. Сотрудник закрыл связанное обращение, клиент получил квитанцию с тем же ID операции. Баланс до и после составил 4 785 900,00 ₸. Прогон использовал учебный канал доставки комнаты.

На прогретом локальном прогоне 180 обычных платежей получили одобрение. p95 скорера составил 2,78 мс, p95 запроса через ASGI и SQLite — 29,32 мс. В отдельном тесте на 500 операциях с fakeredis p95 ML составил 0,49 мс, p95 движка — 8,11 мс. Эти измерения относятся к синтетическим данным и локальному оборудованию.

Результаты Linux-сборки, изолированной проверки жюри и восстановления доступны в проверках выпуска. [Проверки 2.9](https://github.com/foxfordkz-cyber/qadamxbcc/pull/29/checks)
