Разные пакеты Android хранят локальные сессии раздельно. Для Honor следует использовать командный APK. Оба канала обращаются к [мобильному API и кабинетам](https://saq-bol-mobile.onrender.com/wallet/). Уровень публичного тарифа и точный серверный коммит по этим запросам установить не удалось.

В 2.8 уже действовали роли, история переводов, 15-минутный Cooling-Off, Guardian, обращения, аналитика и SOC. В этой работе изменены выдача APK и проверка подписи, перенос хранилища, квитанция и клиентский PDF, контраст карты, объяснение сценария звонка, раздельный учёт событий Guardian и представление доказательств SOC. После интеграции изменений команды сохранена выписка получателя из принятого `main`. Финальный клиент запускается и в старом WebView. Банк и НБК в этой приёмке заменены учебными сервисами.

## Telegram Guardian

22 ноября боту разрешили отправить до трёх сообщений в ранее подтверждённый личный чат. Telegram принял приглашение, запрос согласия и одно уведомление о синтетическом Cooling-Off. Входящий callback подтвердил согласие. Worker сохранил отправку. Пользователь сообщил, что нажал обе кнопки. Повторный запрос к клиентскому API прочитал `SUSPICION_REPORTED`. Отдельного подтверждения `CONTACT_ACKNOWLEDGED` в этом живом прогоне не зафиксировано. Использованы реальный Telegram Bot API, aiogram, изолированная SQLite и fakeredis. Сессия закрыта по лимиту времени.

После проверки исправлено поведение при опережающем нажатии «Есть подозрение». Кнопка подтверждения получения остаётся доступной, поздний ACK записывается один раз, сигнал подозрения сохраняется. Оба порядка проверены на тестовом адаптере. Реальная отправка после этой правки не выполнялась.

## Хранилище, проверки и задержки

На изолированном наборе перенесены 237 строк из SQLite в PostgreSQL. Сверены ID, типизированные строки и связи. Запись в уже заполненную цель отклонена. Два рестарта API сохранили сессии, ledger и ключ идемпотентности. Публичный Render при проверке сообщил `ephemeral_store=true`. Резервная копия работающей публичной базы и Redis требует приватного доступа оператора. Публичный сервис не перезапускался. План финальной синхронизации, отката и проверки копии приведён в [инструкции](PERSISTENCE_AND_RECOVERY_RU.md).

Полный локальный pytest на итоговой объединённой ревизии собрал 796 тестов. Прошли 766, пропущены 30, ошибок и падений не было. Время прогона — 24 мин 27 с. Выборка из 99 пройденных тестов ниже входит в тот же набор. Отдельно в Docker проверены PostgreSQL, Redis, импорт и восстановление. Более ранний CI на `bad75c2` дал 778 пройденных и 3 пропуска на другой ревизии. Актуальное состояние облачных проверок — в [PR #30](https://github.com/foxfordkz-cyber/qadamxbcc/pull/30).

Сравнение 2.8 и первого кандидата 2.9 проводилось в одном Chrome, при ширине 390 px и на одном публичном API. В одном проходе время до формы входа составило 632 → 297 мс, до баланса после входа 1562 → 1138 мс, до баланса после reload 1137 → 941 мс, до квитанции 592 → 634 мс. На изолированном ASGI, без сети и отрисовки, загрузка SOC-дела заняла 52,9 → 56,4 мс, доказательств 53,3 → 72,8 мс, ответ на отмену владельцем 92,5 → 87,1 мс. Одного измерения недостаточно для вывода о приросте скорости.

## Проверка командного APK с кодом 17

На физическом Honor VNE-LX1 по публичному HTTPS вошли клиент, сотрудник SOC и администратор платформы. Сотрудник открыл список дел, администратор — управление доступом. В клиентском кабинете открыт предварительный просмотр PDF своей операции. После остановки процесса восстановился клиентский кабинет. Запуск Activity занял 2 284 мс, наблюдение восстановленного экрана заняло 10 927 мс с учётом опроса через ADB. Отдельные запросы к защищённым экранам трёх ролей вернули HTTP 200.

На чистом эмуляторе Android 11 (API 30, WebView 83.0.4103.120) установили те же байты командного APK и обнаружили два доступных поля ввода. [Экран входа на эмуляторе](evidence/release-2.9/android11-login.png)

Из чистого архива исходного коммита собраны showcase и debug с выполнением всех 402 задач Gradle. С отдельной чистой синхронизацией Capacitor сверены все 45 клиентских ресурсов поставляемого APK. У одного текстового файла различаются только окончания строк Windows и Unix, остальные 44 файла совпали побайтово. SHA-256 в таблице относится к фактически установленному и переданному APK.

На объединённой ревизии прошли 187 тестов frontend и 47 тестов модулей Android-кошелька. В Playwright прошли 34 разных сценария с учётом отдельного повторного прогона, 3 пропущены. В первом прогоне загрузка локального тестового ресурса оборвалась с ECONNRESET до входа в Scam Check. При повторе на той же ревизии проверка черновика, языка и повторной отправки прошла. В целевой backend-выборке прошли 99 тестов, 2 пропущены. Ruff прошёл, mypy проверил 132 файла. Проверены сборка Cloudflare и запросы через Worker, включая SSR, middleware, статические файлы и проксирование API.

| Обновление Android | Сверить пакет, SHA-256 и сертификат с манифестом своего канала. Открыть страницу с телефона или по QR | Сайт выдаёт подписанный APK 2.9. Для установки поверх старой версии нужно выбрать тот же канал. [Манифесты и инструкция](RELEASE_DISTRIBUTION_RU.md) |
| Восстановление | Из `backend` с запущенным Docker выполнить `uv run --frozen --python 3.12 python -m scripts.rehearse_release_storage` | Синтетические операции, сессии и журнал сохраняются после двух перезапусков API. Восстановленная копия PostgreSQL сверяется по записям и схеме. [Хранение данных](PERSISTENCE_AND_RECOVERY_RU.md) |

На локальной копии две роли проверили одно обращение на 900 000,25 ₸. После закрытия дела сотрудником клиент получил результат на казахском и русском. Сумма на счёте осталась прежней, сервер продолжал удерживать перевод. Отдельная проверка подтвердила, что клиенту закрыт доступ к выписке получателя из дела SOC.

Во второй комнате проверили семейную защиту через три раздельных сеанса. Клиент включил защиту и запросил перевод на 900 000,25 ₸. Доверенное лицо сверило реквизиты и сообщило о подозрении. При попытке завершить проверку сервер заблокировал перевод. Сотрудник закрыл связанное обращение, клиент получил квитанцию с тем же ID операции. Баланс до и после составил 4 785 900,00 ₸. Прогон использовал учебный канал доставки комнаты.

На прогретом локальном прогоне 180 обычных платежей получили одобрение. p95 скорера составил 2,78 мс, p95 запроса через ASGI и SQLite — 29,32 мс. В отдельном тесте на 500 операциях с fakeredis p95 ML составил 0,49 мс, p95 движка — 8,11 мс. Эти измерения относятся к синтетическим данным и локальному оборудованию.

Результаты Linux-сборки, изолированной проверки жюри и восстановления доступны в проверках выпуска. [Проверки 2.9](https://github.com/foxfordkz-cyber/qadamxbcc/pull/29/checks)
