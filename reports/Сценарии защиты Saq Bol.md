# Как усилить защиту переводов в Saq Bol

Сильная сторона Saq Bol × BCC — клиент и сотрудник безопасности видят одну и ту же операцию с разных сторон. При проверке 21 ноября 2026 года в локальной комнате с историей клиент выбрал получателя из семи контактов и отправил **800,25 ₸**. Списание совпало с суммой квитанции. В той же комнате сотруднику были доступны десять учебных дел, одно из которых проверили по обращению клиента. На подключённом телефоне запустилась версия Android 2.7, тогда как публичная страница установки предлагала 2.6. Перед показом стоит устранить расхождение версий. Следующий приоритет для пилота — измерить, сколько законных переводов приходится задержать ради выявления ещё одного случая принуждения. ## Один вопрос в приложении может прояснить риск

У **TransferGuard** при среднем риске и пропущенных ответах движок запрашивает недостающий контекст. В схеме Saq Bol отсутствие сведений о звонке по умолчанию даёт значение «звонка нет». Предлагаем различать три ситуации — данных нет, клиент ответил, сведения получены из доверенного источника. Если один ответ может изменить решение, спросить на выбранном языке «Кто-то сейчас просит вас сделать этот перевод?». Для обычного перевода сохранённому получателю число нажатий должно остаться прежним. В деле сотрудник должен видеть источник сведений и время ответа. [Правило TransferGuard](https://github.com/your-golden-hour/transferguard-itu/blob/c8da1f67eafc9de0cf8067a08139bd5b72c98092/lib/risk.ts#L13) · [Контекст Saq Bol](../backend/app/schemas/transfers.py#L16)

У **Qaqpan** близкому объясняют риск одной фразой с суммой и обстоятельствами. В нашем семейном кабинете уже видны сумма и получатель. Можно добавить одну причину, на раскрытие которой клиент дал согласие, и предложить перезвонить по сохранённому номеру. **BCC SafeSign** показывает следующий технический шаг для пилота — подпись конкретного перевода ключом устройства владельца. Семейная проверка Saq Bol уже привязана к сумме, валюте и получателю. Для подтверждения владельцем отдельный приёмочный тест должен показать, что изменение реквизитов требует новой подписи, а повторная отправка подтверждения исключает второе списание. [Семейный сценарий Qaqpan](https://github.com/adiletpn/Qaqpan/blob/5fa87067bf89eed5bcff770b3587370af506d57c/api/family.py#L70) · [Подпись в SafeSign](https://github.com/KItsunexdd/sudo-love-me-TIU/blob/a901b2d6347706d020b13bef00f0d5e316d995c0/src/lib/tx/service.ts#L258) · [Семейная проверка Saq Bol](../backend/app/services/family_approval.py#L88)

## На сайте стоит показать два сбора на одну сумму

**DropRadar** даёт посетителю сравнить честный сбор, продавца и транзитный счёт. У Saq Bol уже есть соответствующие тестовые ситуации. На сайте можно поставить рядом две истории с одинаковой суммой поступлений. Посетитель продвигает время и видит, когда быстрый вывод средств изменил оценку одного счёта. Из точки изменения открывается конкретная операция в SOC. Проверка для команды — до поступления нового события обе оценки используют только доступные тогда данные. Проверка для посетителя — он своими словами объясняет, почему множество отправителей само по себе ещё не делает получателя дроппером. [Сценарии DropRadar](https://github.com/aikenmurat1-design/dropradar/blob/1bc435ad050d7f7d05ce3e49f1bba8b7e2230fb6/index.html.#L285-L350) · [Сценарный стенд Saq Bol](../docs/SCENARIO_STAND.md)

## В SOC нужно показать цену каждого порога

**«Чистый счёт»** сравнивает несколько порогов на синтетических выборках. Saq Bol уже сопоставляет действующую политику с одним альтернативным порогом на последних ста операциях. Цена изменения видна в нашем отдельном испытании переводов во время звонка. Модель v3 задержала **168 из 256** случаев принуждения против **130** у v2. Ложных пауз стало **123 из 384** против **116**. Это ещё 38 обнаруженных случаев и семь дополнительных задержек законных переводов на этом наборе. [Сравнение порогов у «Чистого счёта»](https://github.com/ERA216/ITU-Hackathon/blob/bf5b23ec3101bd8fffabad19b55fd75d2a131e07/app/quality.py#L116-L152) · [Сравнение политик Saq Bol](../backend/app/integrations/cases/policy_review.py) · [Парный эксперимент](../docs/MODEL_EVALUATION.md)

Для выбора следующей версии стоит закрепить отдельный период проверки. На нём для каждого порога показать пропущенное мошенничество, ложные паузы на тысячу размеченных законных переводов, долю известных исходов и задержку 95% запросов от приёма API до ответа. Для пилота понадобятся обезличенные результаты расследований и выборка одобренных операций. По открытым исходникам можно сопоставить функции конкурентов. Для вывода о том, чей движок точнее в банке, всем системам потребуется один размеченный набор.
