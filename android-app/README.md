# Qadam Shield для Android

## Показ за три минуты

1. Установите APK 2.0, откройте Qadam Shield и выберите ҚАЗ или РУС. Введите свой демонстрационный логин и пароль. Пароли передаёт владелец стенда отдельно каждому участнику.
2. Под `client_demo` откройте «Переводы», выберите учебного получателя и сумму. Проверьте реквизиты и подтвердите один раз. Вернитесь в историю и откройте квитанцию. «Одобрено» обозначает решение системы оценки риска.
3. В демонстрационных сценариях перевод 900 000 ₸ под давлением звонящего показывает серверную паузу. Откройте пять вопросов, отмените перевод либо обновите статус по завершении таймера. В «Защите» доступны проверка сообщения, журнал тестовых звонков, круг доверия и обращения.
4. Отправьте синтетическое обращение. Сохраните номер, выйдите через профиль и войдите под `admin_demo`. Откройте «Дела» → «Обращения», найдите тот же номер, отметьте обращение, откройте дело и посмотрите историю. В ленте выберите заблокированную операцию и откройте граф.
5. Отдельный режим «Посмотреть демонстрацию» работает автономно с образцами. Он доступен до входа. Рабочие пространства клиента и сотрудника требуют связи с сервером.

Все средства и участники учебные. Достоверную сумму доступного остатка ядро пока не ведёт. На главной показана сумма операций в статусе паузы по данным PostgreSQL. Круг доверия и учебные получатели перевода ведутся отдельно. В режиме Fake Telegram доставка человеку отключена.

## Развёртывание для команды

Внешний сервис запускает только `backend/scripts/mobile_hosted.py` из каталога `backend` командой `python -m scripts.mobile_hosted`. Для Render/Railway используйте контейнер из `backend/Dockerfile`, отдельные PostgreSQL и Redis, TLS и проверку `/health`. Этот процесс применяет миграции и заполняет только пустую учебную базу. Существующий `render.yaml` относится к веб-демо команды.

Переменные сервера:

- `BCC_ENVIRONMENT=demo`, `BCC_BOOTSTRAP_DEMO=true`, `BCC_MOBILE_ENABLED=true`, `BCC_MOBILE_AUTH_MODE=password`.
- `BCC_DATABASE_URL` (postgresql+asyncpg), `BCC_REDIS_URL` (отдельный индекс или экземпляр).
- `BCC_MOBILE_CLIENT_HASH` и `BCC_MOBILE_ADMIN_HASH` — разные хеши scrypt. Имена аккаунтов фиксированы. Мобильный шлюз выдаёт ограниченные по времени сессии Redis и проверяет роль и владельца объекта на каждом запросе.
- `BCC_INTEGRATIONS_ENABLED=true`, `BCC_INTEGRATIONS_ENVIRONMENT=test`, `BCC_INTEGRATIONS_TELEGRAM_MODE=fake`, `BCC_INTEGRATIONS_SIGNING_KEY` задаются на сервере. Для согласованного внешнего Telegram-теста понадобятся отдельно запущенный allowlisted бот и его публичное имя в `BCC_MOBILE_TELEGRAM_USERNAME`.
- Администратор создаёт личную папку через `QADAM_PRIVATE_DIR` и `python -m scripts.mobile_accounts`. Повторный запуск сохраняет существующие пароли. Для получения серверного хеша используется `app.mobile_gateway.passwords.encode`. Секретные значения устанавливаются через менеджер секретов хостинга. Передавайте каждому участнику только его локальный файл.
- Сборка использует доверенный `QADAM_API_ORIGIN` или адрес учебного стенда в `android-app/demo-origin.txt`. Паролей в ресурсах сборки нет. Для постоянного показа задайте постоянный адрес команды и используйте один и тот же Android signing key для обновлений. GitHub Pages содержит только статическую веб-демонстрацию.

Для сборки установите зависимости в `android-app`, выполните `npm run sync`, затем `gradlew assembleDebug` из `android-app/android`. Debug-пакет — `kz.qadamx.bccshield.demo`. Если сертификат предыдущего debug APK отличается, Android потребует удалить прежнюю тестовую версию. Это очистит офлайн-историю и локальные незавершённые черновики. Серверная история сохраняется.

Временный адрес Cloudflare работает, пока запущены шлюз, его база и туннель. При создании нового Quick Tunnel меняется hostname. Проверьте доступность и обе роли перед показом. Для отката остановите отдельный мобильный сервис, отзовите его сессии и восстановите предыдущую сборку. Схема core не менялась.
