# Saq Bol × BCC · Android 2.4

## Қазақша

Клиент аударым жасайды, тәуекел себептерін көреді және операцияны тоқтата алады. SOC қызметкері тиісті аударымды, графты және өтініштің тарихын ашады. Күмәнді скриншоттың мәтіні телефонда танылады. Әр оқу рөліне сервер жеке, мерзімі шектеулі сеанс береді.

Жергілікті іске қосу үшін төмендегі пәрмендерді орындаңыз. Браузердегі 4173-порт Android интерфейсін көрсетеді. `client_demo` үшін қорғалған жергілікті файлдағы `client` мәнін, `admin_demo` үшін `admin` мәнін қолданыңыз. Бастапқы оқу қалдығы 5 000 000 ₸. Сома орындалған синтетикалық аударымдарға қарай өзгереді. Офлайн шолу бөлек үлгі деректерін пайдаланады.

## Запуск на ноутбуке

От корня репозитория запустите мобильный шлюз с отдельными PostgreSQL и Redis.

```sh
docker compose -f docker-compose.android.yml up -d --build --wait
cd android-app
npm ci
npm run vendor
npm run preview
```

Откройте [Android-интерфейс на localhost](http://127.0.0.1:4173) и выберите ҚАЗ или РУС. Для входа под `client_demo` возьмите значение `client`, для `admin_demo` — значение `admin` из локального файла `.local-checks/mobile-access/access.json`. Шлюз генерирует пароли заново при старте. Для сценария CI с отдельными кодами можно установить `QADAM_MOBILE_AUTH_MODE=rehearsal` перед запуском Compose.

1. Войдите в аккаунт клиента. Откройте кошелёк, выберите учебного получателя, отправьте перевод и посмотрите серверную квитанцию. Учебный баланс рассчитывается от начальных 5 000 000 ₸ с учётом исполненных операций.
2. Откройте удержанный перевод с активным звонком, отметьте окончание разговора. Сообщение об обмане отменяет его через платёжное ядро. Через пять минут можно подтвердить собственный выбор. Платёжная пауза проверяется отдельно при решении о переводе.
3. Создайте обращение, запомните номер, выйдите из аккаунта и войдите как `admin_demo`. Откройте то же обращение, связанный перевод и граф.
4. Для веб-версии с приватным Telegram-входом на первом экране есть кнопка «Открыть веб-клиент». Локальный мобильный Compose использует тестовую доставку. «Офлайн-обзор» открывает автономные примеры.

## APK и подключение телефона

**Бесплатный мобильный стенд.** В [отдельном профиле Render](../deploy/render-mobile-free.yaml) работает один сервис Free с SQLite и приватным Redis. При запуске он создаёт новый набор синтетических данных. После сна или перезапуска история и сессии сбрасываются. Операция клиента появляется в SOC того же мобильного стенда. Веб-демо использует свою базу и своего Telegram-бота. В мобильном профиле доставка в Telegram имитируется.

**Тегін мобильді стенд.** Клиенттің аударымы осы мобильді стендтің SOC панелінде көрінеді. Веб-демо бөлек дерекқорды пайдаланады. Тегін сервер ұйқы режимінен шыққанда немесе қайта қосылғанда сессиялар мен аударымдар тарихы жаңадан басталады. Telegram хабарламалары осы стендте имитацияланады.

Для своего экземпляра разверните этот профиль из приватного репозитория в Render. Создайте две учебные учётные записи командой `python -m scripts.mobile_accounts` из `backend/`. Передайте в `BCC_MOBILE_CLIENT_HASH` и `BCC_MOBILE_ADMIN_HASH` только scrypt-хэши двух разных паролей. Сборке APK нужен публичный HTTPS-адрес из поля URL созданного сервиса в переменной `QADAM_API_ORIGIN`.

Нужны JDK 21+, Android SDK 36 и Node.js 22+. Для работы через USB в Windows PowerShell выполните из `android-app` при запущенном локальном шлюзе.

```powershell
$env:QADAM_USB_REHEARSAL = "1"
adb reverse tcp:18001 tcp:18001
npm run sync
Push-Location android
.\gradlew.bat --no-daemon --max-workers=2 assembleDebug
Pop-Location
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Для удалённого стенда задайте `QADAM_API_ORIGIN` равным постоянному HTTPS origin **мобильного шлюза** до сборки APK. В CI используйте одноимённую GitHub Actions variable. Сборка без адреса позволяет открыть автономные сценарии и опубликованный веб-клиент. Пакет debug — `kz.qadamx.bccshield.demo`. Для установки поверх прежней версии требуется тот же ключ подписи.

## Отдельный HTTPS-стенд

Запустите контейнер из `backend/Dockerfile` командой `python -m scripts.mobile_hosted` с рабочим каталогом `backend`. Этот процесс обслуживает `/mobile/v1` и `/health`. Используйте отдельные учебные PostgreSQL и Redis и задайте на сервере:

- `BCC_ENVIRONMENT=demo`, `BCC_BOOTSTRAP_DEMO=true`, `BCC_MOBILE_ENABLED=true`, `BCC_MOBILE_AUTH_MODE=password`.
- `BCC_DATABASE_URL`, `BCC_REDIS_URL` и два разных scrypt-хеша в `BCC_MOBILE_CLIENT_HASH` и `BCC_MOBILE_ADMIN_HASH`. Личные пароли создаёт `QADAM_PRIVATE_DIR=<private-dir> python -m scripts.mobile_accounts`. Функция `app.mobile_gateway.passwords.encode` получает серверный хеш каждого пароля.
- Для учебной доставки `BCC_INTEGRATIONS_ENABLED=true`, `BCC_INTEGRATIONS_ENVIRONMENT=test`, `BCC_INTEGRATIONS_TELEGRAM_MODE=fake` и отдельный `BCC_INTEGRATIONS_SIGNING_KEY`. Приватный Telegram-круг веб-стенда имеет собственные базу и проверку владельца.

## Проверки

```sh
npm test
npm run test:ui
npm run sync
```

Сквозной сценарий Android в GitHub Actions запускает PostgreSQL/Redis, отправляет учебный перевод через скоринг и открывает дело в SOC. Приёмка конкретного телефона и версии APK фиксируется отдельно.
