# Публичные реализации соперников BCC

## Кто усилился после 20 ноября?

### Вывод

К 25 ноября прежние характеристики NEXORA как проекта исключительно для аналитика и Qaqpan как семейной демонстрации с ограниченным кабинетом устарели. Третий изменившийся проект, «Чистый счёт», теперь называется Clean Break. Даты ниже приведены по времени Казахстана (UTC+5).

### Проверенные факты

- **NEXORA AI / SYNAPTIC LABS.** Ветка по умолчанию осталась на 18.11. В рабочей ветке графа 25.11 обновлён экран аналитика. Тест проверяет переход от ребра графа к исходным транзакциям. Другая публичная ветка от 23.11 содержит отдельный сценарий клиента перед переводом, мобильный интерфейс и проверку права аналитика видеть доказательства. Обе ветки прошли публичные прогоны GitHub CI, включая E2E и запуск образов. Авторы помечают клиентскую ветку как ещё не объединённую с основной рабочей линией. [Состояние веток](https://github.com/SaginbekDaniel/SYNAPTIC-LABS/blob/7637a8056dbfb33dd05d3de9c6f5b8a976881135/docs/handoff/EXECUTION_STATE.md#L16) · [Граф и первичные транзакции](https://github.com/SaginbekDaniel/SYNAPTIC-LABS/blob/7637a8056dbfb33dd05d3de9c6f5b8a976881135/apps/web/e2e/graph-workspace.spec.ts#L67) · [Мобильный сценарий](https://github.com/SaginbekDaniel/SYNAPTIC-LABS/blob/43368ff46b788568d34ceee5ac8ae9135728c373/apps/web/e2e/transfer-protection.mobile.spec.ts#L3) · [CI клиента](https://github.com/SaginbekDaniel/SYNAPTIC-LABS/actions/runs/45189449945) · [CI графа](https://github.com/SaginbekDaniel/SYNAPTIC-LABS/actions/runs/45552088092).
- **Чем NEXORA конкурирует.** Аналитик видит, какое движение денег допускали фактические суммы и порядок событий. Алгоритм учитывает неоднозначность данных с точностью до дня. Для проверки перед переводом снимок учитывает время операции и время, в которое о ней стало известно. При неполной информации политика умеет сообщать о нехватке данных. В авторском отложенном наборе из 112 синтетических сценариев политика предупредила или потребовала дополнительную проверку для 29 из 45 мошеннических и 5 из 67 законных, 16 мошеннических пропустила. Тестируются заранее подготовленные снимки, списания денег в этом модуле нет. [Проверки хронологии и остатков](https://github.com/SaginbekDaniel/SYNAPTIC-LABS/blob/ea5ca9c120115e068ada90c508f2d078d6b512c3/tests/unit/test_temporal_flow.py#L16) · [Подготовка снимка](https://github.com/SaginbekDaniel/SYNAPTIC-LABS/blob/43368ff46b788568d34ceee5ac8ae9135728c373/docs/TRANSFER_PROTECTION.md#L40) · [Политика и границы](https://github.com/SaginbekDaniel/SYNAPTIC-LABS/blob/43368ff46b788568d34ceee5ac8ae9135728c373/docs/TRANSFER_PROTECTION.md#L92) · [Контрольный результат](https://github.com/SaginbekDaniel/SYNAPTIC-LABS/blob/43368ff46b788568d34ceee5ac8ae9135728c373/benchmarks/transfer_protection/results/holdout-v1.json#L82).
- **Qaqpan / adiletpn, 22.11.** Последний коммит датирован 21.11 в 20:57 UTC, это уже 22.11 по Казахстану. К семейному сценарию добавлены банковская очередь с причинами, история сессии, сводка и серверные решения аналитика. В тестах аналитик подтверждает получателя для других клиентов или отпускает отложенный перевод. Близкий может ответить через Telegram. В тесте подменён API Telegram. Для коммита успешно прошли задачи API, web и Android в GitHub Actions, опубликован APK. Демо хранит данные в памяти процесса, журнал звонков банка и процессинг симулируются. Сильный конкурент по непрерывности сценария «клиент → близкий → сотрудник» и показу на телефоне. [Данные аналитика](https://github.com/adiletpn/Qaqpan/blob/4b5216a7aa005bdf5a4f3b7ced8074124df42ef1/api/bank.py#L170) · [Проверки решений](https://github.com/adiletpn/Qaqpan/blob/4b5216a7aa005bdf5a4f3b7ced8074124df42ef1/tests/test_robustness.py#L451) · [Семейный ответ в Telegram](https://github.com/adiletpn/Qaqpan/blob/4b5216a7aa005bdf5a4f3b7ced8074124df42ef1/tests/test_telegram.py#L41) · [Хранение](https://github.com/adiletpn/Qaqpan/blob/4b5216a7aa005bdf5a4f3b7ced8074124df42ef1/api/state.py#L1) · [Границы симуляции](https://github.com/adiletpn/Qaqpan/blob/4b5216a7aa005bdf5a4f3b7ced8074124df42ef1/README.md#L65) · [Публичный CI](https://github.com/adiletpn/Qaqpan/actions/runs/44948998694).
- **Clean Break / ERA216, прежнее название «Чистый счёт».** Новый бренд с 23.11, 24.11 исправлено восстановление входа клиента и добавлена ссылка на Render. Код связывает возврат с первоначальным отправителем и суммой. В тестах по жалобе замораживают только спорную сумму невольного посредника, оформляют проверяемую справку, а снятие чужих денег в банкомате требует имитируемой проверки. Это сильная самостоятельная история восстановления для клиента. В README заявлены 172 автотеста, в репозитории опубликована реализация. Базы других банков, биометрия банкомата и процессинг внешних событий смоделированы. ### Оценка и пробелы

Наиболее убедительные сопоставления здесь относятся к отдельным сценариям. Статус репозиторного CI и опубликованный приложением отчёт позволяют судить о разных вещах. Чужие приложения и тесты в ходе этого обзора самостоятельно не запускались. Развёртывание двух веток NEXORA в одной сборке не установлено.

## У кого есть сильное техническое отличие?

### Вывод

SafeSign особенно убедителен в подтверждении точных реквизитов, Sabyr в передаче банковской сигнальной метки между организациями, Fraud Twin в оценке цены защитной меры для банка и честного клиента. Все трое прямо связывают проект с кейсом БЦК. [SafeSign](https://github.com/KItsunexdd/sudo-love-me-TIU/blob/a901b2d6347706d020b13bef00f0d5e316d995c0/README.md#L5) · [Sabyr](https://github.com/theoneeyedking/sabyr/blob/a51b123b6cf3a17282a5f630a8272e034e504c6a/README.md#L12) · [Fraud Twin](https://github.com/shadix23/fraud-twin/blob/24605206623a216188f4ff6c85f3c5d8eac08792/README.md#L3).

### Проверенные факты

- **BCC SafeSign / KItsunexdd, 20.11.** Проект по адресу `sudo-love-me-TIU`. Владелец подписывает хеш согласованных реквизитов с помощью WebAuthn и ML-DSA-65. Для рискованного перевода вторая подпись включает хеш первой. В серверном API и Playwright есть проверки изменения суммы, повторного подтверждения и согласования. Последнее содержательное изменение UI сделано 20.11, последний SHA в тот же день добавил пустой текстовый файл. Демо допускает программный ключ, использует демо-персонажей и файловое хранилище либо память без межпроцессной блокировки. [Серверная проверка операции](https://github.com/KItsunexdd/sudo-love-me-TIU/blob/a901b2d6347706d020b13bef00f0d5e316d995c0/src/lib/tx/service.ts#L258) · [Привязка второй подписи](https://github.com/KItsunexdd/sudo-love-me-TIU/blob/a901b2d6347706d020b13bef00f0d5e316d995c0/src/lib/tx/service.ts#L298) · [Сквозной тест](https://github.com/KItsunexdd/sudo-love-me-TIU/blob/a901b2d6347706d020b13bef00f0d5e316d995c0/e2e/demo.spec.ts#L72) · [Ограничения](https://github.com/KItsunexdd/sudo-love-me-TIU/blob/a901b2d6347706d020b13bef00f0d5e316d995c0/README.md#L184) · [Последний UI](https://github.com/KItsunexdd/sudo-love-me-TIU/commit/ce39b5ec1c571e3e4422f1bdb8c79d8d3eb78173).
- **Sabyr / theoneeyedking, 19.11.** Смарт-контракт Hyperledger Fabric связывает отметку получателя с организацией, которая её подписала. В Go-тестах банк Б читает отметку банка А, а попытка одной организации подписаться другой отклоняется. Реализована идемпотентность записи. Команда поставляет сеть из двух тестовых организаций. В сквозном Python-тесте перевода, семейного отказа и сигнала второму банку реестр заменён на память. Это технически подкреплённая демонстрация обмена между двумя банками. [Контракт](https://github.com/theoneeyedking/sabyr/blob/a51b123b6cf3a17282a5f630a8272e034e504c6a/ledger/chaincode/sabyr/contract.go#L97) · [Тесты двух банков](https://github.com/theoneeyedking/sabyr/blob/a51b123b6cf3a17282a5f630a8272e034e504c6a/ledger/chaincode/sabyr/contract_test.go#L83) · [Сквозной тест и его подмена](https://github.com/theoneeyedking/sabyr/blob/a51b123b6cf3a17282a5f630a8272e034e504c6a/backend/tests/test_demo_scenario.py#L1) · [Тестовая сеть](https://github.com/theoneeyedking/sabyr/blob/a51b123b6cf3a17282a5f630a8272e034e504c6a/ledger/README.md#L3).
- **Fraud Twin / shadix23, 25.11.** Сильное отличие в том, что банк может сравнить меры защиты по доле утраченных денег и числу затронутых честных операций. Опубликован эксперимент, в котором обучение идёт на четырёх синтетических семействах и проверка на пятом. Авторский артефакт приводит среднюю долю выведенных денег 44,5% для правил и 2,2% для модели в этих фиксированных сценариях. Отдельная проверка демонстрирует предел предупреждения первой жертвы на свежих реквизитах. Авторы также публикуют ухудшение результата при новом поиске сценариев и прямо ограничивают выводы синтетикой. Последние изменения 25.11 затрагивают интерфейс и презентацию. [Условия и результат](https://github.com/shadix23/fraud-twin/blob/24605206623a216188f4ff6c85f3c5d8eac08792/model/benchmark.json#L3) · [Код оценки](https://github.com/shadix23/fraud-twin/blob/24605206623a216188f4ff6c85f3c5d8eac08792/model/train.py#L169) · [Проверки клиента](https://github.com/shadix23/fraud-twin/blob/24605206623a216188f4ff6c85f3c5d8eac08792/sim/tests/test_client_check.py#L35) · [Границы результата](https://github.com/shadix23/fraud-twin/blob/24605206623a216188f4ff6c85f3c5d8eac08792/README.md#L103) · [Изменение интерфейса](https://github.com/shadix23/fraud-twin/commit/dde9002e7a39ee29b945b5e5b71990100df06c8b).

### Оценка и пробелы

Протокол подписи, обмен тестовых организаций и моделирование потерь решают разные задачи. Для сопоставления банковской эффективности потребовались бы одинаковые данные и одинаковое определение вмешательства. В этих публикациях такого испытания нет.

### Вывод

Среди уже известных проектов «Тихий код» особенно нагляден по реакции на продолжающееся давление. QORNET интересен по проверке финансовых оснований для расследования, несколько одноимённых Qorgan следует различать по владельцам.

### Оценка и пробелы

Основой служат публичные репозитории, их исходники, тесты, файлы результатов и указанные прогоны GitHub Actions. У включённых репозиториев GitHub указывал `fork: false`. Это свойство репозитория, а состав команды требует отдельного источника. Для прежнего meirz911/qorgau-ai публичный API вернул 404 и Git не предоставил анонимный доступ, поэтому его текущую реализацию и активность подтвердить не удалось.
